Temu 店铺监测插件 · 使用说明（v22.3 库存归零 + B路径假上架静默恢复）
========================================

【分工】
  本插件（装在你日常 Chrome）负责：
    · 在售商品限流监测 + 严重/一般分级
    · 即时飞书告警（新限流 / 等级升级）
    · 每天 09:30 / 16:30 定点汇总（始终列当前限流池 + 编辑链接）
    · 可选：写入飞书多维表格 + 严重限流建飞书任务
    · 多店空闲轮巡
    · 【v22.2】插件报错自动转发飞书
        插件运行出错（轮巡 / 前台轮巡 / 必提醒 / 消息处理 / 飞书发送失败
        / 页面未捕获异常 / SW 未处理拒绝）会经同一个告警 Webhook 发一张红色
        报错卡片到你飞书，标题带「机器名标签」区分是哪台电脑。
        · 同一根因 30 分钟内只发一次（按错误签名去重，跨 SW 回收存活）
        · 设置页填「机器名标签」（如「运营机」），留空显示「未命名机器」
        · 复用告警 Webhook，不另配通道；不写多维表、不建任务
        · 边界：SW 被强杀那一刻的顶层崩溃来不及发（进程已终止），
          其余 try/catch 内的错误都能可靠上报
    · 【v22.2】前台轮巡成功率修复
        前台变体全查（popup 按钮 / 每 3h 闹钟）新开 tab 时，原来盲等 12 秒，
        Temu SPA 慢渲染就来不及抓到变体 → 被判「非商品页」跳过（日志里 Agnis /
        HomeCove 新开 tab 常失败、复用老 tab 才成）。
        现改为：content-front 拿不到数据会带退避重试 ~20s；background 不再盲等，
        而是监听该 tab 上报，真拿到变体数据才关 tab（最多等 25s）。
        日志完成行带 ok=N/3，能直观看到这一轮几个店抓成了。
    · 【v22.2】前台风控 / 网页打不开提醒
        前台商品页弹人机验证（captcha / 滑块 / "Verify you are human"）或
        因网络原因打不开时，插件会发一张红色飞书卡片提醒你：
        · 人机验证：content-front 扫页面命中 captcha/风控关键词 + 验证码容器
          → 卡片标注「人机验证 / 风控拦截」，附命中标志和页面片段
        · 网页打不开：background 新开 tab 25s 内 content-front 都没注入/没上报
          → 检查 tab 若是错误页/非 temu 域 → 卡片标注「网页打不开 / 加载失败」
        · 同一店同一原因 30 分钟内只发一次（独立去重，不和插件报错挤占）
        · 复用告警 Webhook，不另配通道
        · 收到提醒后：到该店 Temu 前台人工过验证 / 检查网络，
          再点 popup「📦 前台变体全查」复测即可
        · 边界：纯慢渲染（tab 还在正常 temu 域加载中）不提醒，只记日志，
          避免网络稍慢就刷屏
    · 【v22.3】库存归零提醒 + B 路径假上架静默恢复
        · pageQuery 里 SKU 的 realStock/virtualStock 从 >0 变为 0 时发橙色飞书卡
        · 限流筛选把在售清单污染成子集后关筛选：B 路径静默重建全量清单，
          不再把「子集→全量」多出来的商品当成新上架点名（A 路径 v22 已防）
        A 数量：countStatus 在售 N 变化 → 防抖确认后飞书（数量卡）
          · 按接口 mallId 归属店铺（不再只靠 DOM 顶栏店名）
          · 同一新值需连续命中 ≥2 次且间隔 ≥3 秒才发
          · 大幅下降（≥50% 或 ≥3）需 3 次 + 12 秒
          · 归零不走 A 发卡（真清零靠 B 清单）
          · 轮巡切店期间静默数量卡，只同步基准 + 扫清单
          · 回弹到原基准直接取消，不告警
          · 【v20】未确认（pending）绝不触发清单扫描
        B 点名：扫「在售中」清单（仅干净全量视图）
          - 下架：上轮有、这轮没有 → 点名 + 编辑链接（立即）
          - 上架：新进先记 pending，连续两轮仍在售才点名（防抖动）
          - 【v19.4】整店 tabCount=0 需连续 ≥2 次才当真清零；
            近 2 分钟内 countStatus>0 时拒绝假 0（防 loading 误报）
          - 【v20】content 返回 trust=full-onsale 才写基准；
            筛选/视图未就绪 → untrusted，本轮放弃、不动基准
          - 【v20】数量确认后才约 B；轮巡/手动仍可独立扫 B
        限流池【v21】：明细必须与 chip「商品流量待关注 N」对齐
          - 主动扫筛选未收窄时，拒绝把整页在售当待关注（修限流池少计）
          - 被动本页徽标短清单只并入、不覆盖更完整名单
          - pool 条数 < chip 时自动补扫（90s 冷却）；可信筛选可整体替换
        限流基线【v19.4】：全局冷却 ID 不写进本店 snapshot；
          新店首次只 seed 不推飞书（修 HomeCove 首轮 15 条误报）
        与服务器赛狐可能双报：同一 productId 插件侧 6 小时冷却；
        卡片带「插件·后台」字样，便于和赛狐卡区分。

  公司服务器赛狐仍跑上下架（selectStatus=12）。
  赛狐慢/漏时，以本插件后台扫描为准先报。


一、限流等级
-----------
  前提：商品【在售】且有限流信号（流量待关注 或 近期有下降）

  🔴 严重限流（满足任一）
    · SKU 货号以 VIP 开头 → 自有商品
    · SKU 货号以 JM 开头，且带「热销款」标签 → 黑猫渠道

  🟠 一般限流
    · 有限流，但不满足严重条件

  ❌ 已下架 / 已终止商品即使显示限流徽标 → 不报
  ❌ 同一商品 6 小时内不重复即时推（等级升级为严重除外）
  ❌ 切换店铺不会把已有限流再推一遍（v18：chip 未升高只静默记入）


二、上下架 A+B 时机
-----------------
  · 当前店：页面一返回 countStatus，数量有变 → 先挂 pending（不发数量卡、不扫清单）；
    同一新值再命中且间隔达标 → 发数量卡，约 6 秒后再扫清单点名
  · 回弹（毛刺）：pending 期间读数回到原基准 → 取消 pending 与已约扫描，飞书不推
  · 筛选态（点了「商品流量待关注」等）：countStatus 忽略，不写在售基准；
    清单扫描前会强制清筛选，清不掉则本轮放弃
  · 其它店：约每 15 分钟闹钟 + 电脑空闲/锁屏 ≥ 4 分钟 → 轮巡切店并扫描
    （轮巡中数量卡静默，靠 B 点名）
  · 手动：popup「轮巡所有店」立刻扫
  · 升级后每店第一轮只建基准，不告警（避免历史库存误报）


三、安装
------
1. chrome://extensions → 开发者模式 → 加载已解压（本文件夹）
2. 从旧版升级：扩展开关【关掉再打开】（必须，否则仍是旧 SW）
3. popup 顶部应显示：后台：v22.3-库存归零+B路径假上架静默恢复


四、配置
------
1. 飞书群机器人 Webhook → 设置页粘贴 → 测试飞书
2. 【v22.2】机器名标签（报错转发用）→ 设置页填写（如「运营机」）
   · 插件报错时飞书卡片标题带上它，方便区分是哪台电脑
   · 留空显示「未命名机器」；报错复用上面的告警 Webhook，不另配
3. （可选）多维表 / 任务：
   · 企业自建应用 App ID / App Secret
   · 多维表格 app_token + table_id
   · 勾选「严重限流时创建飞书任务」
   · 应用权限：bitable 读写、task 创建；把应用加为表格协作者
4. 必提醒默认 09:30、16:30（可改）


五、日常
------
1. 保持登录，留一个 https://agentseller.temu.com/goods/list 标签
2. 新限流会即时推红/橙卡；定点时推当前限流池（带编辑链接）
3. 在售数量「确认后」推数量卡；点名卡带商品链接
4. 电脑空闲约 4 分钟会轮巡各店（流量 + 在售清单）
5. 手动切店：限流仍按 v18 静默吸收；数量按 mallId 归属 + 防抖
6. 浏览时尽量少长时间停在「商品流量待关注」筛选态（插件会忽略该态 count，
   并在自己扫描前清筛选；用户手点筛选不会被强行抢走，只是不写基准）


六、多维表建议字段
----------------
  店铺 | 商品名 | productId | SKC | SKU货号
  限流类型（待关注/近期下降/两者）
  严重等级（严重/一般）| 热销款 | 编辑链接
  最近推送时间 | 判定原因


七、常见问题
----------
· popup 非 v21-限流池对齐chip：关开插件开关
· 待关注 N · 限流池明显更少：v21 起会补扫对齐；仍少请导出日志看 scanWatchList trusted=
· 切店刷出 12→0→12 / 15→4→15 数量卡：v19.3+ 防抖；v20 起毛刺也不会再约清单扫描
· 真实下架数量卡晚几秒～十几秒：有意设计（防抖）；点名在数量确认后再扫，或等轮巡
· 归零不发数量卡：有意设计，整店清零由 B 清单 tabCount=0 点名
· 点了「待关注」后短暂不写在售数：有意设计（筛选子集不是全店）
· 切店还在刷旧限流：确认已是 v18+ 静默规则；关开一次
· 刚升级就报一堆下架：不应发生（首轮只建基）。若发生请导出日志
· 下架数量卡有了但没有点名：当时不在该店页面 → 等空闲轮巡或点「轮巡所有店」
· 上架要等两轮轮巡才报：有意设计（二次确认），防扫表抖动
· 和赛狐各报一次：同一商品 6h 内插件不重复点名；赛狐侧仍可能再推
· 多维表没写入：检查 app 权限、协作者、字段名
· 严重判成一般：确认列表能看到 SKU货号列与「热销款」
· 没收到报错卡但插件异常：先查设置页 Webhook 是否填、机器名是否对；
  同一根因 30 分钟内只发一次；SW 被强杀那刻来不及发属正常边界
· 报错卡刷屏：不会——同签名 30 分钟去重；飞书侧故障时也打冷却戳不重试
· 收到「前台访问异常」红卡：该店前台弹了人机验证或网页打不开；
  去该店 Temu 前台人工过验证 / 查网络，再点「📦 前台变体全查」复测；
  同店同原因 30 分钟内只发一次，不会刷屏


说明：凭证与业务数据只存本机；告警/报错发到你配置的 Webhook / 多维表。
