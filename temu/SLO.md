# Temu 监测 · 告警 SLO（短文）

> 2026-08-28 · 对齐插件 **v22.3** + 服务器赛狐。  
> 用途：投诉分级、是否热修、护栏松紧。详细历史见 `ROADMAP.md`。

---

## 1. 通道与仲裁

| 信号 | 通道 | 业务以谁为准 |
|------|------|----------------|
| 限流 / 待关注 / 下降 | 仅插件 | Temu 后台（在售 ∩ 限流） |
| 在售数量 / 下架点名 / 上架点名 | **插件 A+B + 赛狐** | **Temu 后台**；赛狐可慢、可双报 |

### 双通道策略 A（已采纳）

- **都报**；插件卡片带 **「插件·后台」**；赛狐卡无此字样。  
- **接受偶尔两张**（同一商品两端各一）。  
- 插件侧：productId **6h** 冷却；数量同 from→to **30min** 不重复。  
- **不做**：为去重而关掉任一通道；不为双报当 P0 热修。

## 2. 目标（SLO）

| ID | 项 | 目标 | 违反时 |
|----|----|------|--------|
| P0-1 | **串店**（A 店事件记到 B 店） | **0** | 立即热修 |
| P0-2 | **切店限流刷屏**（已有 productId 再次即时推） | **0** | 立即热修 |
| P0-3 | **数量毛刺双卡**（如 15→4→15 各报一次） | **0** | 立即热修 |
| P1-1 | 真下架（当前店、清单可扫全）插件漏报 | 应报；延迟见下 | 查 B 路径 / 锁 / 基准 |
| P1-2 | 真新增限流（chip 升高 + 新 ID）漏报 | 应报 | 查静默吸收是否过宽 |
| P2-1 | 与赛狐双报 | **可接受** | 不热修；只优化文案 |
| P2-2 | 赛狐晚于后台 | **可接受**（见延迟） | 不关插件 A+B |
| P2-3 | 必提醒缺链接 / 迟到数分钟 | 尽量带链接 | 非 P0 |

### 延迟（参考，非硬超时杀进程）

| 场景 | 期望 |
|------|------|
| 当前店在售数量确认后 | 约 ≥3s 防抖后；大幅下降约 ≥12s |
| 当前店下架点名 | 数量确认后约 6s 内可触发 B；或轮巡扫到 |
| 它店下架 | 下一轮空闲轮巡（idle ≥ ~4min + 闹钟） |
| 赛狐上下架 | 约 15min 一轮 + 平台同步延迟，允许 15–30min+ |
| 限流即时 | chip **真升高**且新 ID；切店未升高只静默吸收 |

## 3. 明确不承诺

- 同事关闭 Chrome / 无 `goods/list` 时，**插件不保证**任何实时告警（靠赛狐上下架备份）。  
- 在售 **> 一页** 且扫描残缺时，B 可能 skip（防假下架）→ 可能漏点名，数量 A 仍可能报。  
- 赛狐漏拉时整轮 skip → **宁可不报，不假下架**。  
- 前台变体 / SKU 规格 / 多维表为次要信号，故障不自动升 P0。

---

## 4. 投诉怎么处理

1. 要：**店名、时间、卡片全文、popup 含 bgVersion 截图**。  
2. 对照上表：  
   - 撞 **P0** → 热修 + 加时间线单测。  
   - **P1** → 排期修，观察是否复现。  
   - **P2 / 双报 / 赛狐慢** → 记录，默认不发版。  
3. **观察窗**（如全员升 v19.3 后 48h）：非 P0 不发版。  
4. 发版前：`temu-plugin/check.ps1` 必须绿。
